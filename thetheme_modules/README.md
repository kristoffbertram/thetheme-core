# thetheme-core modules reference

The engine. Every file here is **project-agnostic** and synced verbatim across
deployments — never hand-edit a copy in a project; change it here and re-publish.
Per-project data is injected via filters (the carve-out contract).

Loaded by `bootstrap.php` (`thetheme_core_boot()`), in filename order, after WP
core is available.

| File | Purpose | Key API / hooks | Project conventions it relies on |
|---|---|---|---|
| `acf-loader.php` | Registers ACF blocks from `thetheme_blocks/` (child + parent) by folder, so ACF reads each `block.json` and renders the file its `acf.renderTemplate` names. Also includes each block's `fields.php` on `acf/init` and its optional `block.php` once at registration time, and registers no-op fallbacks for legacy block names. | `thetheme_block_dirs()`; hooks `init` (blocks), `acf/init` (fields), `acf/blocks/wrap_frontend_innerblocks`. **Carve-out filters:** `thetheme_acf_legacy_blocks` (default `[]`); `thetheme_log_registered_blocks` (default `false`) — opt in to log every registered block name on an admin request. | `thetheme_blocks/<name>/{block.json,template.php,fields.php}`, plus an **optional** `block.php` — a registration-time include, not a render file (see `README.md` § *Scaffolding doctrine*). Legacy list supplied by `thetheme_functions/app/acf-legacy.php`. |
| `subsites.php` | Multi-subsite engine: register subsites, resolve the current one (by section / page-template / condition), pick template-parts, enqueue per-subsite assets, and enqueue the per-subsite editor stylesheet into the block-editor canvas as a native `<link>`. | `thetheme_register_subsites()`, `thetheme_get_registered_subsites()`, `thetheme_is_section()`, `thetheme_post_is_in_section()`, `thetheme_resolve_current_subsite_id()`, `thetheme_get_template_part()`, `thetheme_enqueue_subsite_assets()`, `thetheme_resolve_editor_css_rel()`, `thetheme_enqueue_subsite_editor_styles()`; hooks `wp_enqueue_scripts`, `enqueue_block_assets`. **Fallback-path filters:** `thetheme_default_stylesheet`, `thetheme_default_script`, `thetheme_default_editor_stylesheet`. | Subsites registered by the project (call `thetheme_register_subsites()` from `thetheme_functions/app/subsites.config.php`). Paths `thetheme_template-parts/<id>/`; the no-subsite fallbacks default to `assets/{css,js}/www/*` and are filterable (see `README.md` § *Where asset paths come from*). The editor entry must exist per declaring subsite — a missing file is an early `return`, i.e. **no theme CSS in the canvas at all** (logged under `WP_DEBUG`). When exactly one subsite is registered its `editor` entry resolves even with no post id, so new posts get it too; see `README.md` § *One registered subsite is always the answer*. |
| `editor.php` | Block-editor hardening + theme typography/colour setup: disables on-demand/separate core block assets, dequeues default block CSS, registers font-size scale, and derives the editor colour palette from the theme SCSS. Carries **no** editor-style injection — that is `subsites.php`. | `thetheme_register_core_block_style_reset()` (on `after_setup_theme` 1), `thetheme_dequeue_core_block_styles()` (on `wp_enqueue_scripts` 100); `add_theme_support` for post-thumbnails, font sizes, line-height, colour palette, disable-custom-gradients, an EMPTY editor-gradient-presets and the estate spacing scale (editor-spacing-sizes); `thetheme_disable_drop_cap()` on `block_editor_settings_all`. **Opt-out filter:** `thetheme_reset_core_block_styles` (default `true`) — false unhooks the whole reset. | Reads colour vars from `thetheme_src/css/theme.scss` (`@theme { --color-*: #hex }`) — a **runtime** read of the SCSS source, so that file must exist on the server. Note the dequeue is `wp_enqueue_scripts`, front end only: WP's block CSS still reaches the editor. The gradient and spacing declarations are what switch core's own presets off — for a classic theme, declaring `editor-gradient-presets` / `editor-spacing-sizes` at all sets `defaultGradients` / `defaultSpacingSizes` to false — which is why the gradient set is deliberately empty. Drop cap has no theme support at all, so the settings tree is filtered on its way to the editor. |
| `defaults.php` | Baseline theme supports, plus the WordPress defaults the package adjusts everywhere: HTML5 markup, responsive embeds, page excerpts with no ellipsis, emoji removal, oEmbed host script removal, and the removal of core's group inner-container injection. | `add_theme_support('title-tag')`; `thetheme_remove_emoji_support()` (on `init`), `thetheme_excerpt_more()`, `thetheme_remove_wp_embed()` (on `wp_footer`), `thetheme_remove_group_inner_container()` (on `init`). **Filters:** `thetheme_html5_markup`, `thetheme_responsive_embeds`, `thetheme_page_excerpts`, `thetheme_excerpt_more_text`, `thetheme_remove_emoji_support`, `thetheme_remove_wp_embed` (all default on / empty string), plus `thetheme_restore_group_inner_container` (**default `false`** — the one that is off by default, because returning true puts core's markup back). | Deliberately does **not** declare `automatic-feed-links` (it was cancelled out by the feed-link removal in `security.php`) or `post-formats` (unused editor UI). The group unhook targets `wp_restore_group_inner_container` on `render_block_core/group`, which core only registers as live when the site has no `theme.json` — i.e. on every site this package converts. See `README.md` § *WordPress injects a div into every group block*. |
| `body-classes.php` | CSS hooks on the document: slug and section classes on `<body>`, category-id classes on `<body>` and `.post`, and the assigned page template as an admin `<body>` class. | `thetheme_add_slug_body_classes()`, `thetheme_add_category_body_post_classes()`, `thetheme_admin_body_template_class()`. **Opt-out filter:** `thetheme_body_classes` (default `true`). | Additive only — it removes and overrides nothing, so it is safe on by default. On a top-level page the section resolves to the page itself; the originals emitted a bare `parent-` there. |
| `security.php` | Removes WordPress output nothing consumes, and gates what trades a real capability. | Essential (no filter): `rsd_link`, `wp_generator`, `wp_shortlink_wp_head`, XML-RPC off, `X-Pingback` removal, array-`s` coercion. Also strips the pingback/multicall XML-RPC methods, blocks user enumeration via `?author=N`/REST users/oEmbed, and **closes every JSON and XML surface by default** — REST behind auth, feed endpoints 404, core XML sitemap off, oEmbed off. **Filters:** `thetheme_rest_requires_auth` (**true**), `thetheme_public_rest_routes` (`[]`), `thetheme_disable_feeds` (true), `thetheme_enable_xml_sitemap` (**false**), `thetheme_disable_oembed` (true), `thetheme_block_user_enumeration` (true), `thetheme_remove_feed_links` (true), `thetheme_hide_admin_bar` (true), `thetheme_login_error_message` (generic string), `thetheme_redirect_author_archives` (true), `thetheme_disallow_file_edit` (true), `thetheme_rest_requires_auth` (**false**), `thetheme_security_headers` (map). | Six of the originals' eleven `wp_head` removals targeted hooks that no longer exist or were never registered; they are not reproduced. HSTS and CSP are deliberately absent from the header default — set those at the server. |
| `images.php` | Responsive image helper, plus an opt-in stripper for WordPress's default intermediate sizes. | `thetheme_image($id, $size, $class, $as_array)` — returns `<img>` markup with srcset/sizes; `thetheme_remove_default_image_sizes()` on `intermediate_image_sizes`. **Carve-out filter:** `thetheme_removed_default_image_sizes` (default `[]` — a no-op until a theme opts in). | The stripper is opt-in because at least one theme renders `medium_large` directly; a default-on version would blank those images silently. See the docblock before using it — stripping the defaults on a theme that registers no sizes of its own leaves `thumbnail` + `full` and serves full-resolution images to every device. |
| `templating.php` | Template helpers used by live markup. | `fgc($theme_relative_path, $echo = true)` — inlines a file from the theme directory; path-traversal guarded. | 14 call sites across the estate (subsite headers, block templates, components). Not a dev tool. |
| `debug.php` | Debug output, called by nothing that ships. | `dump($var, $title)` — styled `print_r`. | Deliberately separate from `templating.php` so a stray call is obvious in a diff. |
| `wp-login.php` | Stylised login screen — inlines a stylesheet into the login `<head>`. | `thetheme_login_css()`, `thetheme_login_css_rel()`; hook `login_enqueue_scripts`. **Path filter:** `thetheme_login_stylesheet` (default `assets/css/wp-login.css`; `''` switches it off). | Optional `assets/css/wp-login.css`, or wherever the filter points. No subsite route — the login screen has no queried page to resolve one from. |

## Carve-out filters (project data lives in the app layer)

| Filter | Default | Supplied by |
|---|---|---|
| `thetheme_acf_legacy_blocks` | `[]` | `thetheme_functions/app/acf-legacy.php` — returns/append legacy block names |
| `thetheme_reset_core_block_styles` | `true` | the app layer — return false to keep WordPress's own block CSS while a conversion writes its parity CSS. Must be set by `after_setup_theme` priority 0; see `README.md` § *Switching the reset off* |
| `thetheme_default_stylesheet` | `assets/css/www/app.css` | the app layer — theme-relative path of the front-end stylesheet when no subsite resolved |
| `thetheme_default_script` | `assets/js/www/app.js` | the app layer — same, for the front-end script |
| `thetheme_default_editor_stylesheet` | `assets/css/www/editor.css` | the app layer — used when the resolved subsite declares no `editor` (receives the resolved subsite id, or `null`, as a second argument) |
| `thetheme_rest_requires_auth` | `true` | the app layer — false reopens the REST API to anonymous callers |
| `thetheme_public_rest_routes` | `[]` | the app layer — route prefixes that stay anonymous while the gate is on |
| `thetheme_disable_feeds` | `true` | the app layer — false lets /feed/ answer again |
| `thetheme_enable_xml_sitemap` | `false` | the app layer — **true if the site has no SEO plugin and needs a sitemap** |
| `thetheme_disable_oembed` | `true` | the app layer — false lets other sites embed this one |
| `thetheme_removed_default_image_sizes` | `[]` | the app layer — names of WordPress's default intermediate sizes to stop generating. Empty means do nothing; see `images.php` for the two traps before opting in |
| `thetheme_login_stylesheet` | `assets/css/wp-login.css` | the app layer — the login screen's only path route; see `README.md` § *Where asset paths come from* |
| `thetheme_restore_group_inner_container` | `false` | the app layer — true puts core's `div.wp-block-group__inner-container` back inside every `core/group` while a theme rewrites selectors that reach through it. A **conversion runway, not a setting** (see `README.md` § *Putting the div back*); must be set by `after_setup_theme` priority 0 |

Subsite registrations are not a filter but a registration call:
`thetheme_register_subsites([...])` from `thetheme_functions/app/subsites.config.php`.
